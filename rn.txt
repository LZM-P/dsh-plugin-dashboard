refactor: unify the name to dsh-plugin-dashboard and take the template edge off the README

The package shipped as dsh-plugin-rack while the repository, the install
instructions and the plugin id said dashboard -- two specs for one plugin, which
is how a user ends up with it installed twice. Everything is now
dsh-plugin-dashboard: package name, cordis patch id, route prefix, SELF, state
directory, the custom request header, localStorage keys, and the routes listed
in the header comment.

Two references stay on purpose. SELF_NAMES and the self-row check keep
'dsh-plugin-rack' so a profile that installed the older name is still
recognised as this panel rather than offered as an unrelated plugin. The README
migration section keeps the old plugin-rack directory path because it describes
where old versions put their files.

README also lost the machine-written rhythm: thirteen sentences that all ended
in an em dash plus a clarifying clause are now ordinary statements, and the
opening section heading is "用来干什么" instead of the templated
"它解决什么问题". Three remaining dashes are a table placeholder and two
natural English parentheticals.

Tests were updated to the new route and header names; the self-check's own
route-extraction comment had been rewritten to a path the regex no longer
matched, which is what surfaced the missed index.js header. All five suites pass
and the 21 routes line up.
